# Phase 01: Auth + Workspace Foundation

## Overview

Thiết lập nền tảng multi-user tối giản cho MVP nội bộ: email/password auth, workspace concept, roles, session guard.
Mọi phase sau đều phụ thuộc vào phase này.

## Why Better Auth

- TypeScript-native, support Drizzle ORM adapter + PostgreSQL
- TypeScript-native email/password auth, sessions, and organization/workspace plugin
- Workspace/organization plugin có sẵn
- Tránh build auth từ đầu (YAGNI)
- `/ck:better-auth` skill available trong project

## Deferred

- Password reset/change password, email verification, invite email, and Google social login are intentionally deferred until internal usage proves they are needed.
- Full workspace-owned data isolation stays in Phase 02.

## Requirements

**Functional:**
- Email/password login (primary)
- Signup with email/password and immediate session
- Workspace: each workspace = team/organization
- Roles: `owner`, `admin`, `member`, `viewer`
- Session management (cookie-based, 30-day expiry)

**Non-functional:**
- Auth state available server-side (RSC) và client-side
- Server-side dashboard guard protects all `/dashboard/*` routes
- Rate limiting on auth endpoints (inherit existing middleware)

## Architecture

```
Better Auth (packages/auth-config/)
  ├── DB Adapter: Drizzle + PostgreSQL
  ├── Plugin: organization (workspace + roles)
  │     └── Custom role: viewer (read-only)
  └── Provider: email/password only

Dashboard layout guard (apps/web/src/app/dashboard/layout.tsx)
  └── Protect /dashboard/* routes → auth.api.getSession() → redirect /login or /workspace

Auth Routes (apps/web/src/app/api/auth/[...all]/route.ts)
  └── toNextJsHandler(auth) (Next.js App Router)

Session (apps/web/src/lib/auth-client.ts)
  └── createAuthClient + organizationClient plugin
```

## DB Tables (Better Auth managed)

Better Auth với organization plugin auto-creates:
- `user` — id, email, name, emailVerified, createdAt
- `session` — id, userId, expiresAt, token
- `account` — id, userId, provider, providerAccountId (for OAuth)
- `verification` — id, identifier, value, expiresAt
- `organization` — id, name, slug, createdAt (= workspace)
- `member` — id, organizationId, userId, role, createdAt
- `invitation` — id, organizationId, email, role, status, expiresAt

## Implementation Steps

1. **Install Better Auth**
   ```bash
   cd apps/web && npm install better-auth
   ```

1b. **Register `packages/auth-config/` trong monorepo**
   - Add vào root `package.json` workspaces: `"packages/auth-config"`
   - Add vào `turbo.json` pipeline — `auth-config` depends on `db`:
     ```json
     "packages/auth-config#build": { "dependsOn": ["packages/db#build"] }
     ```
	   - Create `packages/auth-config/package.json`:
	     ```json
	     { "name": "@repo/auth-config", "main": "./src/index.ts", "dependencies": { "better-auth": "^1.x", "@repo/db": "*" } }
	     ```
   ⚠️ Thiếu bước này → TypeScript import `@repo/auth-config` sẽ fail ngay lần đầu build.

2. **Create `packages/auth-config/`** package
   - `packages/auth-config/src/index.ts` config:
     ```ts
     betterAuth({
       database: drizzleAdapter(db, { provider: 'pg' }),
       emailAndPassword: {
         enabled: true,
         autoSignIn: true,
         requireEmailVerification: false,
       },
       session: {
         expiresIn: 60 * 60 * 24 * 30, // 30 days
         updateAge: 60 * 60 * 24,
       },
       plugins: [
         organization({
           allowUserToCreateOrganization: true,
           creatorRole: 'owner',
           // viewer is a custom role (not built-in) — must define explicitly
           // ⚠️ CRITICAL: must include project+task read or viewer sees blank dashboard
           roles: {
             viewer: {
               permissions: {
                 organization: ['read'],
                 member: ['read'],
                 invitation: [],
                 project: ['read'],
                 task: ['read'],
               }
             }
           }
         })
       ]
     })
     ```
   - `baseURL` from env (`BETTER_AUTH_URL`)

2b. **Generate Drizzle schema via CLI**
   ```bash
   cd packages/auth-config
   npx @better-auth/cli generate --adapter drizzle --output ../db/src/schema/auth-schema.ts
   ```
   Auto-generates all Better Auth tables (user, session, account, verification, organization, member, invitation).
   Export from `packages/db/src/index.ts` → available for Drizzle ORM queries.

3. **Add env vars**
	   ```
	   BETTER_AUTH_SECRET=<32-char random>
	   BETTER_AUTH_URL=https://your-domain.com (or http://localhost:3002)
	   ```

4. **Auth route handler** — `apps/web/src/app/api/auth/[...all]/route.ts`
   ```ts
   import { auth } from '@repo/auth-config';
   import { toNextJsHandler } from 'better-auth/next-js';
   export const { GET, POST } = toNextJsHandler(auth);
   ```

5. **Dashboard server layout guard** — protect `/dashboard/*`
   ```ts
   // apps/web/src/app/dashboard/layout.tsx
   import { auth } from '@repo/auth-config';
   import { headers } from 'next/headers';
   import { redirect } from 'next/navigation';

   export default async function DashboardLayout({ children }) {
     const session = await auth.api.getSession({ headers: await headers() });
     if (!session) {
       redirect('/login?redirect=/dashboard');
     }
     if (!session.session.activeOrganizationId) redirect('/workspace');
     return children;
   }
   ```
   ⚠️ Next `15.3.9` cannot use Better Auth's Node APIs in middleware without canary-only `experimental.nodeMiddleware`, so the server layout guard is the supported path.

6. **Client-side auth** — `apps/web/src/lib/auth-client.ts`
   ```ts
   import { createAuthClient } from 'better-auth/react';
   import { organizationClient } from 'better-auth/client/plugins';

   export const authClient = createAuthClient({
     baseURL: process.env.NEXT_PUBLIC_APP_URL,
     plugins: [organizationClient()] // Required for authClient.organization.* methods
   });

   // signIn/signUp are objects with .email()/.social() methods — destructuring is safe
   export const { signIn, signOut, signUp, useSession } = authClient;
   ```
   ⚠️ `organizationClient` plugin is mandatory — without it, `authClient.organization.*` (create, invite, setActive) don't exist.

7. **Login page** (`/login`) — Email/password form only

8. **Signup page** (`/signup`) — Name + email + password + workspace name

9. **Workspace selector** — After login, if user has multiple workspaces → select one
   - Store selected workspace in session/cookie
   - All subsequent API calls include `organizationId`

10. **Update Hono API** — Extract `organizationId` from session for all endpoints
    ```ts
    // middleware in api-app
    const session = await auth.api.getSession({ headers: c.req.raw.headers });
    if (!session) return c.json({ error: 'Unauthorized' }, 401);
    // activeOrganizationId is null if user hasn't selected a workspace yet
    if (!session.session.activeOrganizationId) {
      return c.json({ error: 'No workspace selected' }, 403);
    }
    c.set('userId', session.user.id);
    c.set('workspaceId', session.session.activeOrganizationId);
    ```

## Risk Assessment

- **Session table naming**: Better Auth uses `session` table; ensure no collision with existing tables. Use auto-generated schema from CLI.
- **DB migration**: Better Auth creates new tables; existing tables unaffected until Phase 02.
- **Null `activeOrganizationId`**: User can be authenticated but have no active workspace — API must return 403 and redirect to workspace selector, not silently pass null.
- **No self-serve recovery in internal MVP**: Forgot/reset/change-password are deferred. If a tester forgets a password, reset manually until an email provider is intentionally added.
- **Admin demotion guard**: `canDemoteRole()` must verify workspace has ≥1 owner after demotion. If admin tries to demote the last owner → return 400 "Workspace must have at least one owner".
- **`packages/auth-config` monorepo setup**: Must add to root `package.json` workspaces + `turbo.json` pipeline before first build (see Step 1b). Skipping this causes TypeScript resolution failure.
